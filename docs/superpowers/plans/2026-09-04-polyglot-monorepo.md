# CryptoLab Polyglot Monorepo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reorganize CryptoLab into independently runnable Python and TypeScript applications backed by an installable shared Python package, with reproducible `uv` and `pnpm` workspaces.

**Architecture:** Three Streamlit applications and one React/Vite application live under `apps/`; reusable Kamino and backtest logic lives in `packages/arblab` with a `src` layout. A small shared path module provides stable repository resource paths, while root `just` recipes delegate dependency and task execution to `uv` and `pnpm`.

**Tech Stack:** Python 3.11+, uv workspaces, pytest, Streamlit, React 18, TypeScript 5, Vite 5, pnpm workspaces, Playwright, just

---

## File and Ownership Map

- Create `uv.lock`: reproducible Python resolution generated by uv.
- Create `pnpm-workspace.yaml`: Node workspace package selection.

- Create `pnpm-lock.yaml`: reproducible Node resolution generated by pnpm.

## Implementation Rules

- Begin in a dedicated worktree created with the `using-git-worktrees` skill. Do not implement on the current dirty branch.
- Capture binary-safe staged and unstaged patches plus hashes of untracked source-tree files before creating the worktree. Apply the tracked patches in the migration worktree and commit that exact WIP snapshot separately before structural edits. Never overwrite the pre-existing modifications in `.gitignore`, strategy/report code, tests, or the existing July specification.
- Use `git mv` for tracked files so history remains legible.
- Use the `test-driven-development` skill for new path behavior and application smoke coverage.
- Use the `verification-before-completion` skill before claiming completion.
- Do not execute `legacy/exchange-arbitrage/main.py` or perform live RPC/market calls during default verification.
